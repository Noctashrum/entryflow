# 竞途有序 · EntryFlow

[打开在线工作台](https://noctashrum.github.io/entryflow/)

面向参赛团队的赛规核验与投递管理工作台。贴入赛规和项目摘要，保留每个候选要求的原文出处，人工核验后把材料与待处理门槛转换成投递任务。

## 十分钟复现

1. 安装 Node.js 22.13 或更新版本，进入仓库目录。
2. 安装依赖并启动。

   ```sh
   npm ci
   npm run dev
   ```

3. 打开终端显示的本地地址，选择「载入示例」。赛规根据第九届传智杯 AI 创新应用挑战赛的[官网页面](https://www.boxuegu.com/matchTrack/detail/?id=10039)摘编。项目摘要使用虚构学生项目。
4. 选择「提取门槛与材料」。在核验页打开「投递复核」，选择下方任一预设再点「复核资料」。点击结果行号可跳到赛规或项目摘要，对照原文后勾选建议并加入投递清单。
5. 在「候选门槛」手动填写核验结果和备注，选择「生成投递清单」。打开一条复核任务的「复核问题及引用」，修改负责人、备注和状态。刷新后检查进度，最后选择「导出 Markdown」，核对复核问题及两类原文引用。

验证生产构建与逻辑测试。

```sh
npm run build
node --test
npm run preview
```

`dist/` 可交给静态站点托管。静态版支持完整投递闭环和本地证据检索。

### 官方赛规样例的三个复核问题

| 复核问题 | 用样例验证 |
| --- | --- |
| 截止与资格 | 核对赛规中的 2026 年 11 月 18 日与个人赛条款，再查看摘要中的「全日制本科生独立开发」线索。 |
| 仓库与开发证据 | 对照公开仓库或开放评审访问的条款与摘要中的私有仓线索，确认 Git 演进记录缺少明确证据，再把「核对仓库与评审权限」加入清单。 |
| 待补交付物 | 打开演示视频赛规，核对 5–8 分钟、1080p 及 AI 协同复现要求，依据摘要中的视频尚未完成线索加入「核对演示视频」。 |

「自定义问题」可以输入「演示视频有没有时长限制？」并查看同一问题命中的两类资料。样例日期来自赛规摘编，实际投递以赛事通知为准。

### 复现跨赛段核验

1. 在录入页的「赛段示例」卡选择「载入赛段示例」，再选择「提取门槛与材料」。这份演示同时保留省赛、国赛和通用参赛要求。顶部「载入示例」仍可打开原来的省赛工作流样例。
2. 将「核验赛段」设为「全部阶段」，在投递复核中选择「自定义问题」。输入「国赛作品提交什么时候截止？」并运行，查看国赛条款与日期 **2026-12-27**。再问「比较省赛和国赛的作品提交截止时间」，分别打开省赛 **2026-11-18** 与国赛 **2026-12-27** 的原文。
3. 切到「省赛」后再问国赛截止，查看赛段不一致提示。切到「国赛」，可核对 **2026-12-10 至 2026-12-21** 的报名窗口和作品截止日期。引用显示赛段与原文章节，点击行号跳回录入文本。
4. 在国赛范围生成清单。仓库、Git 历史、Prompt 记录、README、视频和技术文档会作为六类材料。奖项和评审标准留在原文区域。修改一项进度，切到省赛应看到独立核验和清单，再切回国赛可取回原进度。导出的 Markdown 会标明核验赛段和原文出处。

这两个演示沿用同一个虚构项目。赛段安排摘编自[赛道官方页面](https://www.boxuegu.com/matchTrack/detail/?id=10039)。

### 复核的数据流

1. 将当前赛规和项目摘要按句切分，保留来源、行号和列位置。
2. 识别赛段标题和时间、提交、评审、奖项等章节。先按所选赛段和问题范围筛选，再排序检索，给出带原文位置的本地候选与缺口提示。
3. 配置模型后，可额外把命中的片段交给模型生成建议。服务端对照检索结果核验模型返回的引用，按原文回填。
4. 用户对照证据勾选建议并加入清单。任务带着问题、引用与跟踪状态，随清单一起保存和导出。

## 可选的 AI 复核

本地静态工作流无需密钥。需要模型复核时，将 [.env.example](.env.example) 复制成 `.env` 并填写服务端环境变量。

| 变量 | 用途 |
| --- | --- |
| `ENTRYFLOW_AI_BASE_URL` | OpenAI 兼容 API 的基础地址，含所需版本路径 |
| `ENTRYFLOW_AI_API_KEY` | 服务端 API 密钥 |
| `ENTRYFLOW_AI_MODEL` | 服务提供方支持的模型 ID |
| `HOST`、`PORT` | 本机服务器监听地址和端口，默认为 `127.0.0.1:4173` |

```sh
npm run build
node --env-file=.env server/index.js
```

打开服务地址，在「投递复核」执行一次本地复核后点击「请求模型复核」。同源服务根据问题检索赛规与项目摘要，只把命中片段和问题发给模型。建议和可定位的原文引用会显示在模型复核区，可选作跟进任务。服务异常时仍可用本地证据。保持 `.env` 在本机，公开仓库提供的 [.env.example](.env.example) 只含变量模板。

自动化验证使用模拟模型服务覆盖片段发送、引用校验与错误处理。连接实际模型需要填写服务端配置并发起请求。

## 实现与使用边界

- 界面使用 Vite、原生 JavaScript 和 CSS。浏览器端按中文关键词、条款模式提取候选要求并排序检索，引用保留可定位的赛规行号。
- 支持粘贴赛规与导入 TXT、Markdown、CSV、JSON 或带文字层的 PDF。PDF 文字由按需加载的 PDF.js 提取。截图或扫描件需要先转写成文字。
- 草稿、核验、复核结果和进度保存在当前浏览器。同一建议只加入一次。变更赛规或项目摘要后需要重新提取和复核，复核任务按最新出处重新采纳。同一赛事、项目及来源中，重新生成时保留要求与引用均相同的材料进度和手动任务。
- 省赛、国赛和全部阶段的核验结果与清单分别保存。通用条款可出现在多个范围。范围冲突或缺少适用条款时，界面提示核对范围与资料。
- 数据来自录入内容，规则抽取会遗漏未识别的表述。可手动补录门槛和清单项，并通过官方入口递交材料。
