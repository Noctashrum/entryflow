# 竞途有序 · EntryFlow

[打开在线工作台](https://noctashrum.github.io/entryflow/)

面向参赛团队的赛规核验与投递管理工作台。贴入赛规和项目摘要，保留每个候选要求的原文出处，人工核验后把材料与待处理门槛转换成投递任务。

## 十分钟复现

1. 安装 Node.js 22.13 或更新版本，进入仓库目录。
2. 安装依赖并启动。

   ```sh
   npm ci
   npm run dev
   ```

3. 打开终端显示的本地地址，选择「载入示例」。赛规根据第九届传智杯 AI 创新应用挑战赛的[官网页面](https://www.boxuegu.com/matchTrack/detail/?id=10039)摘编。项目摘要使用虚构学生项目。
4. 选择「提取门槛与材料」。打开任一赛规行号，在录入页检查对应原文。回到核验页，把门槛标记为符合、不符合或待确认，也可以填写核验备注。在证据检索中搜索「演示视频」，查看命中的赛规原文。
5. 选择「生成投递清单」。修改一项材料的状态、负责人和备注，查看进度，刷新页面确认数据仍在，最后选择「导出 Markdown」。

验证生产构建与逻辑测试。

```sh
npm run build
node --test
npm run preview
```

`dist/` 可交给静态站点托管。静态版支持完整投递闭环和本地证据检索。

## 可选的 AI 复核

本地静态工作流无需密钥。需要模型复核时，将 [.env.example](.env.example) 复制成 `.env` 并填写服务端环境变量。

| 变量 | 用途 |
| --- | --- |
| `ENTRYFLOW_AI_BASE_URL` | OpenAI 兼容 API 的基础地址，含所需版本路径 |
| `ENTRYFLOW_AI_API_KEY` | 服务端 API 密钥 |
| `ENTRYFLOW_AI_MODEL` | 服务提供方支持的模型 ID |
| `HOST`、`PORT` | 本机服务器监听地址和端口，默认为 `127.0.0.1:4173` |

```sh
npm run build
node --env-file=.env server/index.js
```

打开服务地址，在「核验门槛」输入检索词并点击「复核当前关键词」。同源服务使用当前录入文本检索赛规片段，把匹配片段、查询词和项目摘要发给已配置的模型，并将建议及可定位的原文引用呈现在页面上。核验结论由用户更新。保持 `.env` 在本机，公开仓库提供的 [.env.example](.env.example) 只含变量模板。

## 实现与使用边界

- 界面使用 Vite、原生 JavaScript 和 CSS。浏览器端按中文关键词、条款模式提取候选要求并排序检索，引用保留可定位的赛规行号。
- 支持粘贴赛规与导入 TXT、Markdown、CSV、JSON 或带文字层的 PDF。PDF 文字由按需加载的 PDF.js 提取。截图或扫描件需要先转写成文字。
- 草稿、核验和进度保存在当前浏览器。变更赛规或项目摘要后需要重新提取和核验。同一赛事、项目及来源中，重新生成时保留要求与引用均相同的材料进度和手动任务。
- 数据来自录入内容，规则抽取会遗漏未识别的表述。可手动补录门槛和清单项，并通过官方入口递交材料。
