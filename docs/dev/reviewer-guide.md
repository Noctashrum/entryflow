# 评审复现与 Prompt 迭代索引

从[十分钟复现指南](../../README.md#十分钟复现)启动 EntryFlow，或直接打开[在线工作台](https://noctashrum.github.io/entryflow/)。无需密钥即可完成录入、人工核验、清单生成、进度保存和导出。样例赛规来自官方渠道摘编，样例项目为虚构项目。

本页定位实际发出的模块 Prompt、AI 实现和验收反馈。产品 Prompt 在成果验收阶段整理并发送，各模块原始提示和早期反馈保留在相应的[开发记录](README.md)。以下失败数据来自当轮日志。首版缺陷中有些在功能首次入库前已修复，可通过日志核对当时的输入、输出和追加提示，通过可达提交和测试复验修复结果。

## 1. 赛规漏识别与摘要误匹配

1. **编排提示**。证据 agent 收到「返回真实截取片段和对应行号，不在缺失时猜测、不给自动通过且交给用户确认」的要求，随后收到官方赛规摘编的覆盖范围。 [初始提示与摘编追加提示](agent-evidence.md#初始提示词)
2. **AI 首版**。证据 agent 实现 `analyzeRules` 和 `retrieveEvidence` 接口，保留候选条款及原文行号。编排者以同一份官方摘编和虚构摘要调用初版抽取器。 [实现记录](agent-evidence.md#实现记录--2026-11-16)
3. **验收失败**。首版抽到 4 项门槛、3 项材料，漏报第 3 行组别和第 7、8、12 行的仓库、Git 历史及技术 PDF。资格和截止日期误用了项目用途句。 [首轮核验记录](agent-evidence.md#初版核验反馈)
4. **追加提示**。「列出每个材料而非合并到相邻条款，要求低置信度不显示证据。」证据 agent 增加个人赛与组别识别，拆开六项材料，并按门槛类型筛选摘要。 [反馈与修订](agent-evidence.md#初版核验反馈)
5. **修复提交**。[赛规提取与检索](https://github.com/Noctashrum/entryflow/commit/c828ada)和[原文行号与导入回归](https://github.com/Noctashrum/entryflow/commit/758e1a8)。
6. **复测**。运行 `node --test tests/evidence.test.js`。用站内「载入示例」提取赛规，确认 7 项门槛及第 7–12 行的 6 项材料。第 2 行匹配摘要学籍句，原创与日期缺少强摘要线索时留空。 [验证记录](agent-evidence.md#验证)

## 2. 窄屏进度与键盘焦点

1. **编排提示**。界面 agent 按录入、核验、清单三阶段实现桌面与移动布局，并记录后续验收。 [首轮提示词](agent-interface.md#首轮提示词)
2. **AI 首版**。界面组件向工作流提供动态内容区与辅助区，宽屏并排、窄屏依 DOM 顺序堆叠。 [初版界面提交](https://github.com/Noctashrum/entryflow/commit/ba4aafc)
3. **验收失败**。390px 视口进度与导出约在页面 4761px 处。补做 Tab 检查时，390px 的首个核验备注框底部约 808px，落入从 770px 开始的固定操作栏。 [实测记录](agent-interface.md#迭代与浏览器验收)
4. **追加提示**。「仅在清单阶段的窄屏把『投递进度』和导出置于任务之前（保持桌面双栏）」并使键盘和视觉顺序一致。此前迭代 Prompt 也明确要求排查清单滚动及键盘焦点。 [第二轮](agent-interface.md#第二轮提示词) · [第三轮](agent-interface.md#第三轮提示词)
5. **修复提交**。清单阶段在窄屏先放进度再放任务，宽屏保持双栏。`keepFocusedControlInView()` 在控件与操作栏重叠时滚动聚焦控件。 [窄屏与焦点修复](https://github.com/Noctashrum/entryflow/commit/5a9b1df)
6. **复测**。当轮 390px 进度区移到约 309px，先于约 549px 的任务列表；Tab 聚焦备注时自动滚动 46px，备注框在操作栏上方留约 8px。320、390、768、1440px 均无文档横向溢出。这是当轮页面尺寸记录，当前版本可按相同步骤复验顺序和可见性。 [浏览器复测](agent-interface.md#迭代与浏览器验收)

## 3. 内容变更与引用失效

1. **编排提示**。工作流 agent 收到「保留原正常流程与本地既有数据，变更后过期或更新不乱继承」的任务，并与检索 agent 对齐双来源引用结构。 [模块 Prompt](agent-rag-workflow.md#收到的模块-prompt) · [接口反馈](agent-rag-workflow.md#合同反馈)
2. **AI 首版**。复核流程按赛规和摘要定位出处，人工采纳建议后写入带引用任务，刷新可恢复。同一资料输入保留适用进度。 [实现与当轮记录](agent-rag-workflow.md#迭代反馈)
3. **验收失败**。开发检查发现摘要首行加空行、只比较修剪后的值会保留旧行号；浏览器从「待补交付物」切到「自定义问题」也曾误报资料已更新。 [失败与反馈](agent-rag-workflow.md#迭代反馈)
4. **追加提示**。「请最小改动区分资料变更与问题切换（后者可提示运行当前问题或省略），如合适补回归。」资料比对保留原始空行，查询切换单独处理。 [追加提示与实现](agent-rag-workflow.md#迭代反馈)
5. **修复提交**。[带引用清单与工作流修复](https://github.com/Noctashrum/entryflow/commit/9345931)和[本轮验收记录](https://github.com/Noctashrum/entryflow/commit/9160cfa)。
6. **复测**。运行 `node --test tests/workflow.test.js`。先切换问题，确认提示运行所选问题；切回后仍可看上次结果。再插入摘要首空行并提取，确认旧复核引用失效；重新复核才可使用新行号。普通材料和同来源、同要求的进度仍按工作流规则保留。 [测试说明](agent-rag-workflow.md#验证)

## 评审现场操作

1. 载入示例后提取门槛及材料，在「投递复核」选择「仓库与开发证据」。打开一处赛规引用和一处项目摘要引用，核对各自原文；摘要缺少 Git 演进证据时保留待办。
2. 采纳一项建议并生成清单。填写负责人、备注和状态，刷新后导出 Markdown，核对原问题与两类原文引用。
3. 按需在 390px 宽度检查进度位置与 Tab 焦点。仅切换问题与改动摘要各做一次，检查状态提示、清单进度及引用是否更新正确。

静态版的本地检索无需模型。模型复核需同源 Node 服务和兼容 API 配置，项目以模拟上游验证上下文发送和引用拒绝，第三方真实推理未在这些验收记录中执行。 [复核数据流](../../README.md#复核的数据流) · [模拟上游验证](agent-rag-engine.md#修订和验证)
