# EntryFlow 开发记录

竞途有序-面向参赛团队的赛规核验与投递管理工作台

## 编排者产品 Prompt
  
  这条 Prompt 由编排者整理，并在项目验收阶段发给工作流 agent。各模块文件保留实施过程中实际发生的提示、反馈、迭代与验证。
  
  > 作为产品负责人，请用多 agent Vibe Coding 构建 EntryFlow（竞途有序）。目标是让准备参赛的学生和团队把赛规、项目摘要与核验结果转成可追踪的投递任务。用户先录入赛规和项目摘要，随后对照原文确认门槛，最后生成清单、更新负责人和进度并导出。将界面、规则证据和工作流划给不同 agent 编写代码，保留各轮实际提示、反馈、修正和验证。每个提交对应已落地的模块或迭代。
  
  ## 2026-11-16 · 赛道核验与任务拆分

来源为[第九届传智杯 AI 创新应用挑战赛官方详情](https://www.boxuegu.com/matchTrack/detail/?id=10039)。静态 HTML 仅包含页面框架。依据该页面加载脚本中的公开只读请求，读取了主办方接口返回的赛道正文（赛道编号 10039）。[官方页面的数据来源](https://gateway.boxuegu.com/portal-marketing/competition/track/detail?id=10039&userId=&includeDetail=true) · [东莞理工学院赛道材料摘要](https://cs.dgut.edu.cn/info/1034/19118.htm)

- 该赛道以 Vibe Coding 构建可复现的应用为主题，技术栈不限。参赛规则指定个人赛，并按正式全日制学籍与学校类型选择研究生组、A 组、B 组或 C 组。工作台服务通用竞赛，该样例遵循此赛道的个人赛规则。
- 省赛报名、提交同为 2026 年 11 月 18 日截止。作品入口在完成缴费后从赛事个人中心查看，确切时刻以系统公告为准。
- 省赛材料包含公开或开放评审权限的 GitHub/Gitee 仓库、真实细粒度 Git 提交历史、至少三条核心功能的完整 Prompt 迭代链、十分钟复现 README、5–8 分钟 1080p MP4（至少 2 分钟 AI 协同复现），以及不超过 30 页的 PDF 技术文档。Prompt 的文本导出、截图或录屏可用于提供过程证据。国赛安排需按所处阶段另行核对。
- 页面定位为有真实工作产出的投递工作台。将输入的赛规和项目摘要绑定到核验结果，展示来源和行号，保留人工判断，从材料条款与待处理门槛生成可跟踪、可导出的清单。
